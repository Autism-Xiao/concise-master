# Concise 管理系统 · 使用说明

一套前后端分离的后台管理系统：**React 19 + Vite + shadcn/ui** 前端（`concise-admin`）+ **NestJS 12 + TypeORM + MySQL 8.4** 后端（`concise-server-node`），内置 RBAC 权限、多租户、水印、验证码、审计日志等能力。

---

## 1. 目录结构

```
concise/
├── concise-server-node/     # 后端（NestJS）
│   ├── src/                 # 源码（modules/ 按业务模块划分）
│   ├── migrations/          # 数据库迁移（src/migrations）
│   ├── scripts/             # serve.mjs 启动脚本、smoke-* 冒烟脚本
│   ├── sql/                 # 数据库快照
│   ├── tests/               # 单元测试（node --test）
│   └── .env                 # 端口、数据库、Redis 等配置（不入库）
└── concise-admin/           # 前端（React + Vite）
    ├── src/features/        # 按业务域划分的页面与组件
    ├── src/lib/             # http、auth、dict、settings 等基础设施
    └── .env                 # 后端代理地址等配置
```

## 2. 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | 24+ | 后端编译与运行 |
| pnpm | 任意近期版本 | **包管理器，禁用 `npm install`**（会损坏依赖树） |
| MySQL | 8.4 | 服务名 `MySQL84`，默认库 `concise_server` |
| Redis | 6+ | 验证码、权限缓存、限流 |

## 3. 首次启动

```powershell
# 1) 后端：装依赖 → 配 .env → 编译 → 启动
cd concise-server-node
pnpm install --force          # 恢复依赖也用这条
# 编辑 .env：PORT=3000、MySQL 连接、Redis 连接
pnpm run build
node scripts/serve.mjs        # 启动（不要用 nest start --watch）

# 2) 数据库迁移（首次或拉取到新迁移后）
./node_modules/.bin/typeorm migration:run -d dist/shared/database/data-source.js

# 3) 前端：另开一个终端
cd concise-admin
pnpm install
pnpm run dev                  # 默认 http://localhost:5173，占用时自动换 5174
```

前端 dev 服务器会代理 `/backend-api` 到后端（自动读取后端 `.env` 的端口），无需额外配置。

## 4. 默认账号

| 账号 | 说明 |
|---|---|
| `admin` | 平台超级管理员（绕过权限点校验，可看全部租户与平台视角） |
| 其他账号 | 由管理员在「用户管理」创建；普通账号能否自助开通团队取决于 VIP |

> 租户模板角色：每个租户自动生成 管理员 / 编辑者 / 访客 三套内置角色（admin 可管理成员与全部数据；editor 可写业务数据不可删；viewer 只读业务数据 + 个人工作台，不含成员管理、配置类页面与文件库）。

## 5. 常用入口

| 内容 | 地址 |
|---|---|
| 前端页面 | http://localhost:5173 |
| 接口文档（Scalar） | http://localhost:3000/api/docs |
| OpenAPI JSON | http://localhost:3000/api/docs-json |
| Swagger UI 备用 | http://localhost:3000/api/docs-ui |
| 后端健康检查 | http://localhost:3000/api/v1/health |

> 后端端口以 `.env` 的 `PORT` 为准（示例中 3000）。本机 curl 调试需加 `--noproxy "*"`。

## 6. 常用命令（后端）

| 命令 | 作用 |
|---|---|
| `pnpm run build` | 编译（改完代码必须先 build 再重启） |
| `node scripts/serve.mjs` | 启动服务 |
| `pnpm test` | 单元测试（node --test tests/*.test.cjs） |
| `pnpm run lint` / `format` | 代码检查与格式化（husky 提交时会自动跑，不要手动 format） |
| `typeorm migration:run ...` | 执行数据库迁移 |

## 7. 注意事项

1. **包管理只用 pnpm**：`npm install` 会把依赖树装崩，恢复用 `pnpm install --force`。
2. **改完代码要 build**：运行的是 `dist/` 产物，不编译等于没改；判别新旧进程可请求一个新路由，404=旧进程。
3. **重启走 `node scripts/serve.mjs`**，不用 `nest start --watch`。
4. **权限缓存**：直接改数据库里的角色授权后，需要清 Redis 的 `perm:role:*` 或重启服务才生效。
5. **多租户**：平台共享数据 `tenant_id=0`，所有租户可见；前端通过头像菜单「切换租户」改变视角；普通用户自助开通团队需要 VIP（平台超管在「用户管理」授予）。
6. **前后端同批发布**：前端所有数据来自后端 `/api/v1/**`，接口字段变更需两端一起发。
