# Concise 管理系统 · 从零使用手册（功能全走查）

> 适用：线下干净数据（仅 admin 账号 + 干净菜单），逐页走一遍所有功能。
> 后端 `http://localhost:3459/api`，前端 `http://localhost:5173`，账号 `admin`，密码 `admin123`。
> 数据库：当前连 PostgreSQL；MySQL 未动。

---

## 第 0 步：启动与登录

### 0.1 确认后端在跑

```bash
curl http://127.0.0.1:3459/api/v1/health
# 期望：{"status":"ok","db":true,"redis":"ok",...}
```

没跑就启动（后端目录）：

```bash
cd /e/oneself/concise/concise-server-node
node dist/main.js
```

### 0.2 启动前端

新开一个终端：

```bash
cd /e/oneself/concise/concise-admin
pnpm dev
# 打开 http://localhost:5173（被占用会自动换 5174）
```

前端会自动把 `/backend-api` 代理到后端 3459 端口，不用额外配置。

### 0.3 登录

1. 打开 `http://localhost:5173`，进入登录页。
2. 输入 `admin` / `admin123`。
3. 拖动滑块验证码到底完成验证 → 点登录。
4. 登录后落地仪表盘，左侧出现 6 个菜单分组。

> 提示：admin 是平台超级管理员，能看全部菜单、绕过按钮权限校验。所以走查时不会出现"没权限"的页面，正好适合全功能验收。

### 0.4 登录后的界面构成

- 左侧：菜单树（6 大分组）
- 顶部：标签页（打开过的页面会变成标签，可关闭）、全屏/主题/通知图标
- 右上角头像菜单：**个人设置、切换租户、锁屏、退出登录**
- 每个列表页通用操作：搜索栏、查询/重置、新增、导入、导出、批量删除、分页

## 第 1 步：仪表盘（`仪表盘 → 查询`）

1. 点左侧「仪表盘」，看概览卡片：用户数、菜单数、日志数等统计。
2. 观察图表和待办区块是否正常渲染（干净数据下多为 0 或空）。
3. 验证点：页面无报错、数字与库一致（当前 user=1、menu=137）。

## 第 2 步：系统管理（11 个页面）

这是核心，按下面顺序走，先建基础数据再建人。

### 2.1 部门管理（`系统管理 → 部门管理`）

1. 点「新增」，建一个部门，如"研发部"，填名称、排序，保存。
2. 在树里选中该部门，点「新增」建子部门"前端组"。
3. 试「修改」改名、「导出」下载 Excel、「删除」删除子部门。
4. 验证点：部门树层级正确，用户管理里选部门时能看到它。

### 2.2 岗位管理（`系统管理 → 岗位管理`）

1. 「新增」岗位"开发工程师"，填岗位编码、名称。
2. 试「导入」：先点「导入模板」下载 Excel，按模板填一行再导入。
3. 试「修改」「导出」「批量删除」。
4. 验证点：导入后列表出现新岗位，编码唯一校验生效。

### 2.3 职级管理（`系统管理 → 职级管理`）

同岗位：新增"P6"→ 导入 → 修改 → 导出 → 删除，流程一致。

### 2.4 用户管理（`系统管理 → 用户管理`）

1. 列表应只有 admin 一行。逐项试：
   - 「新增」：建用户 `test01`，填账号、姓名、密码、手机号，绑定刚才建的部门和岗位，保存。
   - 「重置密码」：给 test01 重置密码。
   - 「分配角色」：暂时跳过（第 2.5 建角色后再回来绑）。
   - 「平台管理员」「VIP 设置」：给 test01 开 VIP（平台级操作，admin 能做），可再取消。
   - 「导入」：下载模板，填一行用户导入（导入的用户会生成随机初始密码并强制首登改密）。
   - 「导出」：下载用户 Excel。
   - 「冻结/解冻」「强制下线」「删除」「回收站恢复」：逐个试。
2. 验证点：用户列表刷新正常；新用户能用重置后的密码登录（可另开浏览器无痕窗口测）。

### 2.5 角色权限（`系统管理 → 角色权限`）

1. 「新增」角色"测试编辑"，填角色名、编码。
2. 给角色「授权」：勾选"数据字典"的查询/新增等菜单和按钮，保存。
3. 回到用户管理，给 test01 绑定"测试编辑"角色。
4. 用 test01 登录（无痕窗口），验证：只能看到被授权的菜单，未授权的看不到。
5. 试「修改」「导出」「导入」「删除」。
6. 验证点：授权保存后 test01 的菜单和按钮按授权收敛；admin 不受影响。

### 2.6 菜单管理（`系统管理 → 菜单管理`）

1. 看菜单树，确认 6 分组 + 子菜单完整、无 smoke 垃圾。
2. 「新增」一个菜单（如"我的测试页"），填名称、路径、图标、类型（目录/菜单/按钮）。
3. 「修改」改名、「导出」快照、「删除」删掉刚建的测试菜单。
4. 验证点：改完菜单后，admin 刷新页面能看到变化（平台管理员直接读全量菜单）。

### 2.7 租户管理（`系统管理 → 租户管理`）

1. 干净数据下租户为空。「新增」租户"测试租户"，填名称、编码。
2. 「分配用户」：把 test01 分配给该租户。
3. 「编辑」租户信息、「查询租户」看列表。
4. 右上角头像菜单「切换租户」切到测试租户，看菜单是否按租户套餐收敛。
5. 切回平台视角（admin）。试「删除」租户。
6. 验证点：切换租户后数据范围变化（客户/订单按租户隔离）。

### 2.8 水印策略（`系统管理 → 水印策略`）

1. 配置全局水印：开启、填水印文字（如"内部测试"），保存。
2. 回头像菜单进「个人设置 → 我的水印」，看是否继承全局策略。
3. 验证点：页面出现水印文字。测试完可关闭。

### 2.9 参数配置（`系统管理 → 参数配置`）

1. 看参数列表（14 条），按分组筛选。
2. 修改一个非关键参数（如某个开关），保存，再「重新加载」。
3. 验证点：改完立即生效；不要动登录/加密相关关键参数。

### 2.10 开放平台（`系统管理 → 开放平台`）

1. 「创建应用」：填应用名，拿到 ClientId / ClientSecret。
2. 「重置密钥」「编辑应用」「创建订阅」「删除订阅」「删除应用」逐个试。
3. 用应用凭证调开放接口（接口文档 `/api/docs`）：`POST /api/v1/open/token` 换 token → `GET /api/v1/open/users`。
4. 验证点：能拿到 token 并成功调用开放接口。

### 2.11 代码生成（`系统管理 → 代码生成`）

1. 选一张表（如 customer），预览生成的字段和代码。
2. 点「执行生成」生成前后端 CRUD 代码（平台级操作）。
3. 验证点：生成的文件出现在约定目录，能编译。**注意：测试完记得还原，别把生成代码留在底座里。**

## 走查中常见问题

- **页面空白/接口 404**：后端可能没重启或跑的是旧 dist。改过代码要 `pnpm build` 再重启。
- **"无权限"**：普通用户没授角色/菜单；admin 不会出现（绕过鉴权）。
- **验证码拖不动**：看后端日志；临时排查可设 `CAPTCHA_ENABLED=false` 重启（测完恢复）。
- **改了角色授权不生效**：清 Redis `perm:role:*` 或用运维→缓存监控清缓存。
- **菜单不显示**：菜单 status 必须为 '1'；平台级菜单只有平台管理员可见。
- **数据想重置**：重跑 `scripts/wipe-to-admin-menus.sql`（先备份），但会清掉你新建的测试数据。
